# MVP運用要件

## 1. 目的と位置づけ

本書は、地域サッカー大会スケジューラーの初期リリース（MVP）について、利用規模、
利用者の操作、データの保存と共有、オフライン利用、性能、費用の前提を定める。

大会規則とスケジュール制約の正本は`AGENTS.md`とし、本書はそれらを変更しない。
本番インフラの比較では、本書とFaaS技術検証の実測値を入力として使用する。
特定のホスティング、FaaS、データベース、ブラウザ保存技術は本書では決定しない。

## 2. 利用者と利用規模

主な利用者は、単一の地域大会を準備・運営する主担当者とする。専門的なIT知識や
開発環境を前提とせず、スマートフォン、タブレット、PCのWebブラウザから利用する。

| 項目 | MVP要件 |
| --- | --- |
| 大会の運用単位 | 単一の地域大会 |
| チーム数 | 1大会あたり最大32チーム |
| コート数 | 1大会あたり最大16コート |
| 試合数 | 1大会あたり最大512試合 |
| セクション数 | 1日あたり最大128セクション |
| 同時利用 | 1大会あたり1〜3人程度。ただし同じデータのリアルタイム共同編集は行わない |
| 生成回数 | 全利用者合計で月100回未満を初期想定とする |
| 入力サイズ | JSON表現で最大1 MB |
| 生成待ち時間 | 生成開始から結果表示まで30秒以内 |
| クラウド費用 | 無料枠超過時を含め、月500円程度を上限の目安とする |

上限を超える入力は処理を開始せず、超過した項目、現在値、上限、利用者が取れる対応を
日本語で示す。制約や上限を黙って緩和して処理してはならない。

## 3. MVPの利用フロー

主要操作は次の順序とする。利用者へ内部ID、JSON構造、ソルバー状態などの実装詳細を
直接操作させない。

1. **大会を作成する**
   - 新規大会を選び、大会名と開催条件の入力を始める。
   - 既存データがある場合は、消去または置換前に確認する。
2. **チーム、コート、大会条件を入力する**
   - 段階的な画面、既定値、入力例、即時バリデーションを使用する。
   - 有効な変更は利用端末へ自動保存する。
3. **日程を生成する**
   - 入力を生成前に検証し、処理中であることと30秒の待ち時間目安を表示する。
   - 通信失敗やタイムアウト時も入力を保持し、再試行方法を示す。
4. **生成結果を確認する**
   - 日程表、対戦表、審判割当て、チーム別予定を通常の利用者向け表示で確認する。
   - 実行不能の場合は、原因、影響、修正候補を日本語で表示する。
5. **印刷またはJSONファイルへ保存する**
   - 会場向けの閲覧・印刷と、バックアップ・受け渡し用のJSON書き出しを提供する。
   - 印刷は保存済み大会から専用snapshotを作り、画面の入力欄、操作、診断、監査値を含めない。
   - 1日目リーグ、2日目同順位リーグ、2日目順位決定トーナメントを、組合せ概要、コート別日程、
     チーム別予定またはトーナメント表の配布順で出力する。
6. **保存データを復元する**
   - 再読み込み時は利用端末の自動保存から復元する。
   - 別端末ではJSONファイルを読み込み、検証と確認を経て復元する。

## 4. データ保存、共有、削除

### 4.1 保存の正本

- MVPでは、利用端末のブラウザ内自動保存を作業中データの正本とする。
- 自動保存には大会入力、生成済み日程、スキーマバージョン、生成条件を含める。
- 有効な最新状態に加え、誤操作から戻せるよう直前の確定状態を1世代保持する。
- 保存期間は利用者が削除するまでとする。ただし、ブラウザ設定や端末管理による
  データ消去を防げないため、重要な大会はJSON書き出しを案内する。

### 4.2 ファイル共有

- 担当者間や端末間の共有には、JSON互換の大会データファイルを使用する。
- JSONには認証情報、端末識別子、内部ログ、スタックトレースを含めない。
- 読み込み時はスキーマと上限を検証し、大会名や更新日時などの概要を表示してから
  現在データを置き換える。
- 読み込みで現在データを置き換える前に、現在状態を直前の確定状態として保持する。
- リアルタイム同期、競合解決、共同編集、公開URLによる結果共有はMVP対象外とする。

### 4.3 クラウドへ送信するデータ

- リモート計算基盤を使用する場合、日程生成に必要な大会入力だけを送信する。
- 計算基盤では入力と生成結果を処理完了後に永続保存しない。
- ログには大会入力、チーム名、生成結果を記録せず、リクエスト識別子、処理時間、
  状態コード、使用量など運用に必要な最小限の情報だけを残す。

### 4.4 削除

- 大会データの削除は確認後に実行し、可能な場合は直前状態から取り消せるようにする。
- 利用者がブラウザ保存を消去する手順と、書き出したJSONファイルは利用者自身が管理・
  削除することを画面上で説明する。
- MVPではクラウドに大会データを永続保存しないため、サーバー側の大会データ削除機能は
  設けない。

## 5. 認証、権限、個人情報

- MVPでは利用者アカウント、ログイン、役割別権限を導入しない。
- 同じ大会を複数人で扱う場合も、JSONファイルを受け渡し、同時編集を避けて運用する。
- 不特定多数への公開サービスや、検索可能な大会一覧はMVP対象外とする。
- 選手登録、氏名、連絡先などの個人情報を入力・保存しない。
- チーム名と大会名は運営情報として扱う。リモート計算で一時送信する可能性を利用者へ
  説明し、不要な情報を自由記述欄へ入力させない。

公開APIを採用する場合、アカウントがないことを濫用対策の免除理由にしてはならない。
入力上限、実行時間上限、同時実行上限、レート制限、Bot対策、予算通知の組合せを
インフラADRで決定する。

## 6. オフラインと障害時の動作

MVPで保証するオフライン動作は、事前にPWAを読み込み大会データを保存した端末での、次の操作とする。

- 大会設定
- 生成済みの日程表、対戦表、審判割当て
- チーム別予定
- 保存済み大会からの印刷用snapshot表示とPDF保存（schema `0.1.0`の閲覧互換を含む）
- 保存済み日程のExcel出力と、全結果・確定順位を保存済みの1日目リーグ結果Excel出力
- 1日目リーグの結果入力、順位確定、自動保存、再読込み
- 2日目同順位リーグの結果入力、総合順位確定、自動保存、再読込み
- 2日目順位決定トーナメントの結果入力、総合順位確定、自動保存、再読込み

オフラインでの日程生成と端末間同期は保証しない。
大会設定の新規入力や変更は端末内へ自動保存できるが、日程生成には通信と安全確認が必要である。

| 状況 | 必須動作 |
| --- | --- |
| 画面の再読み込み | 最新の有効な自動保存を復元する |
| 順位確定中の通信切断 | 形式を問わず通信を使用せず端末内で検証・計算し、成功時だけ保存する |
| 日程生成中の通信切断 | 入力を保持し、不完全な結果を保存せず、再試行を案内する |
| クラウド計算基盤の障害 | 保存済み結果の閲覧を継続し、新規生成が利用できないことを示す |
| 誤った入力・削除 | 確認を表示し、直前の確定状態へ戻す手段を提供する |
| JSON読込み失敗 | 現在データを変更せず、修正可能なエラー内容を日本語で示す |
| ブラウザ保存の消失 | 自動復旧を保証せず、JSONバックアップからの復元を案内する |

## 7. 性能、費用、運用

- 生成開始から結果表示までのエンドツーエンド時間を30秒以内とする。通信、計算基盤の
  起動、求解、応答検証を含む。
- 30秒以内に実行可能解が見つからない場合は、「解なし」と区別してタイムアウトを返す。
- 月100回未満の通常利用、想定を超える繁忙時、濫用時について月額を比較する。
- ホスティング、計算、ログ、監視、データ転送、濫用対策を含む通常月額を500円程度に
  収める。無料枠だけを根拠に恒久的な無料運用を保証しない。
- 費用上限を超える見込みがある場合は、予算通知だけでなくレート制限や実行停止条件を
  設ける。
- 障害調査に必要な機械可読コードと最小限のメトリクスを残し、大会データや個人情報を
  ログへ保存しない。

## 8. MVP対象外

- 利用者アカウント、ログイン、役割別権限
- クラウドデータベースへの大会データ永続保存
- リアルタイム共同編集、端末間自動同期、競合解決
- 公開閲覧リンク、検索可能な大会一覧
- オフラインでの日程生成、端末間同期
- 選手情報、連絡先、その他の個人情報管理
- 本番インフラ製品の選定

これらが必要になった場合は、データ移行、アクセス制御、費用、既存JSONとの後方互換性を
先に定義する。

## 9. インフラ比較への引継ぎ

インフラADRでは、少なくとも次を本書の要件に対して同じ基準で評価する。

- 静的コンテンツ配信、計算基盤、ブラウザ保存の責務境界
- 30秒以内の応答、最大入力、同時利用1〜3人、月100生成未満への適合性
- オフラインで保存済み結果を閲覧できる配信方式
- 大会データを永続保存しない構成とログ最小化
- 認証なしの公開計算資源に対する濫用・課金対策
- 通常月、繁忙月、濫用時の費用と月500円程度の上限
- デプロイ、ロールバック、監視、障害調査、将来の基盤移行

AWS Lambdaのメモリ割当て別測定は、Lambdaが比較後も最終候補に残り、費用または30秒
要件の判断に追加データが必要な場合にだけ実施する。
